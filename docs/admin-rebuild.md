# 运营后台重做（@ankotti/admin-ui 9.6.1，分支 feat/admin-ui-rebuild）

`server/apps/admin` 原来是手写 React + Tailwind + Radix 组件，现在整体换成 admin-ui 9.6.1（和 frontend 同一个 tag）。
外壳是 `AdminShell`，工作标签按需打开，首页固定；地址栏同步成 `/admin/<页>`，用户详情是 `/admin/users/<id>`。
各页面先选 PAGE-TEMPLATES 里的模板再写。`admin-ui-audit src` 0 错误。

本地预览：`node dev/mock-api.mjs 18799`，再 `VITE_API_URL=http://127.0.0.1:18799 pnpm dev`。
截图：`node dev/screenshots.mjs <输出目录> [admin/页 ...]`，出 1440 / 390 / 360 / 1440 深色四张。

## 新增接口（只读，管理员鉴权，`server/apps/api/src/admin-stats*.ts`）

| 接口 | 内容 |
|---|---|
| `GET /v1/admin/stats/overview?days=7\|30\|90` | 付费 / 免费用户、新注册、实收（分，字符串）、已支付订单、新增付费用户、转化批次、手机绑定、云端配置 / 云同步、短信 24 小时、在线设备 |
| `GET /v1/admin/users/:id/cloud` | 云同步元数据，加云端命名配置列表（名字、大小、设备、是否分享、是否设恢复密码）。不含配置内容、分享码和密码哈希 |

顺带修了一个旧 bug：`store.listUsers` 的 tier 条件少写了 `$`，按等级筛选会报 SQL 错误。

## 看板分类卡

```text
【看板分类卡 · 运营总览】
业务类型：订阅会员（§2.3）+ 支付对账（§2.4，只做经营口径，不做差异对账）+ 推广返利（§2.5，只放待办数）+ 客户端运维（§2.9，在线设备）
用途：经营复盘（主）；「此刻」一条只做值班提醒
受众：业主 / 运营
要做的决定：拉新还是促转化；手机号、云同步推得动不动；提现、佣金有没有积压
新鲜度：每分钟自动刷新（不是 3 秒实时档，没有在线人数大屏需求）
数错代价：钱算错是事故，所以金额一律按分用 bigint 累加；人数差几个可以接受
北极星：付费会员数
一级 KPI：新注册、免费→会员转化、实收、手机号绑定率、云端配置使用
下钻：KPI 卡点进用户 / 订单 / 设备 / 分销页（不带筛选；带筛选的下钻还没做）
对比：最近 N×24 小时（含今天，进行中）对紧挨着的前 N×24 小时；比率变化用 pp；转化批次少于 30 人不判断；快照类指标不给变化值，标「当前快照」
时区：Asia/Shanghai，北京日切
查看范围：所有管理员看全量（服务端 admin 鉴权）
告警：无（看板只做展示；短信失败目前不落库）
```

### 指标字典

| 指标 | 口径 | 好的方向 |
|---|---|---|
| 付费会员 | role=user 且有 status=active、未过期（或永久）、等级为 standard/premium 的授权的用户数（试用不算） | 涨 |
| 免费用户 | role=user 用户数 − 付费会员 | 中性 |
| 新注册 | 窗口内创建的 role=user 用户数 | 涨 |
| 免费→会员转化 | 窗口内注册的用户里，窗口结束前有已支付订单的比例 | 涨 |
| 实收 | 窗口内 paid_at 落在窗口、状态仍为 paid 的订单金额（分）。退款后状态变 refunded，不计入 | 涨 |
| 新增付费用户 | 第一笔已支付订单落在窗口内的用户数 | 涨 |
| 手机号绑定率 | phone 非空的 role=user 用户 ÷ 全部 role=user 用户 | 涨 |
| 云端命名配置 / 云同步 | config_profiles 份数（另列已分享、设恢复密码的份数）/ config_sync 用户数 | 涨 |
| 短信（24 小时） | sms_codes 最近 24 小时的条数，对比前 24 小时；另列验证成功条数（consumed_at）。表里只留约 2 天，所以窗口固定 | 中性 |
| 在线设备 | 15 分钟内有心跳、未解绑的设备 | 中性 |
