# Claude Code 加速：网关切换（设计稿）

> 2026-09-28 用户提出。配套服务端是 PowerVPN（`D:\code\powervpn`，方案第 5 期）与 AI 流量加速器中继（sub2api 仓 `accel/`，设计 `docs/ai-traffic-accelerator.md`）。

## 1. 要解决的问题

很多用户直接用 Claude 官方订阅登录 Claude Code（不走任何网关），AI 编程每个请求都带着越来越长的上下文，上行流量极大，节点扛不住。加速器能把每轮请求压成"只发和上一轮不同的部分"，实测上行省约 97%。ProxySplit 要让这类用户**不用懂、不用配**就用上。

## 2. 用户看到的行为

新增「Claude Code 加速」卡片，两种模式：

| 模式 | 含义 |
|---|---|
| **官方默认**（默认） | 不改 Claude Code 任何配置，流量照常经分应用代理出去 |
| **编码模式** | Claude Code 的模型请求先交给 ProxySplit 内置编码端，经所选节点送到落地机中继还原后发官方 |

- **自动切换（默认开）**：当前线路的落地是我们的节点，且中继连得通 → 自动切到编码模式；换成别的线路、断开代理、中继不通 → 自动回到官方默认。
- **手动**：用户随时点「编码模式」「恢复官方默认」。手动选了官方默认后，在同一条线路上自动切换不再把它切回编码；换线路或重新打开自动切换后恢复自动。
- 卡片显示：当前模式、原因（"落地为 PowerVPN 节点，中继延迟 xx ms" / "当前线路不支持加速"）、本次省了多少流量。
- 退出 ProxySplit、停止代理、卸载 → 一律恢复官方默认。

## 3. "是我们的节点且通"怎么判断

两个条件同时满足才算：

1. **是我们的落地**：经当前线路访问中继的健康接口，中继用服务端私钥对随机挑战签名，客户端用内置公钥验签通过。IP 可以变、节点可以换，只认签名，不认名单；不会被伪造。
2. **中继是通的**：同一次健康检查往返成功且延迟正常。运行中每 30 秒复查一次，连续 2 次失败就回到官方默认。

## 4. 怎么让 Claude Code 走编码端

Claude Code 到官方是 HTTPS，客户端只看得到密文，所以**不能**在 TUN 里透明压缩（装根证书做中间人既不安全又易被杀软拦，不采用）。做法是让 Claude Code 主动把请求交给本机：

- 切到编码模式：往 `~/.claude/settings.json` 的 `env` 写 `ANTHROPIC_BASE_URL=http://127.0.0.1:<端口>`，并在键不存在时补 `ENABLE_TOOL_SEARCH=true`（自定义地址时 Claude Code 默认关工具搜索，会多耗 token）。
- 恢复官方默认：首次改之前把原文件原样存档，恢复时**逐字节还原**；用户期间自己改过的键不动（沿用 aigw / 切换器的 restore 实现与快照格式）。
- 用户本来就配了自定义 `ANTHROPIC_BASE_URL`（例如公司的 sub2api 网关）→ 不接管，卡片提示"已在使用网关"。
- 官方订阅登录照常：Claude Code 仍带自己的订阅凭据，编码端和中继只转发、不看不存。
- 已经打开的 Claude Code 会话要重开才生效（环境变量启动时读取），卡片提示这一点。

## 5. 编码端（内置在 ProxySplit）

- 监听 `127.0.0.1` 随机端口，Go 实现，和中继协议逐字节兼容（增量帧 AXD1、续传协议 0.4：请求 ID、断线按字节续传、结束帧校验总长和 SHA-256）。
- 经当前线路的本地入站连中继（专用虚拟地址），连接池预热。
- **中继不通时原样转发**：编码端退化成普通转发，Claude Code 不会因为加速而断；同时触发回到官方默认。
- 只处理 Claude 的模型请求（`/v1/messages`），其他路径原样转发。

## 6. 服务端必须先具备的（PowerVPN / 中继）

- **每用户加速令牌**：由 ProxySplit 服务端（会员账号）或 PowerVPN 面板签发，中继离线验签；不能把公司内部的共享口令发给客户。
- **缓存按用户隔离**：否则 A 可以引用 B 缓存里的对话前缀拼请求，用自己的账号发给官方，套出 B 的对话内容。
- 中继经专用虚拟地址访问；落地机其余回环 / 内网地址一律拒绝（与 VM200 安全修复合并）。
- 按用户统计省流量、可限额。

## 7. 分步实施与验收

1. **验证订阅用户**：一台官方订阅登录的电脑，设 `ANTHROPIC_BASE_URL` 指向灰度编码端跑通对话。
2. **中继多租户**：每用户令牌、缓存隔离、签名健康接口、专用地址；故障注入测试（沿用 accel 的续传测试）全过。
3. **Go 编码端**：与 Rust 中继互通测试（数 1 到 800 逐字节一致、断线续传、中继切换、客户端断开取消）。
4. **ProxySplit 切换器**：模式、自动检测、配置写入与逐字节还原（`restore_test` 同款测试）、界面卡片。
5. **灰度**：先公司内部几台电脑，再发版。
