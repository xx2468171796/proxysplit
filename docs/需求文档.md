# ProxySplit 需求文档（给 UI 设计/实现用）

> 一句话定位：**v2rayN 的「节点 / 订阅 / 内核 / 日志」** ＋ **Proxifier 的「按应用分流」**，合成一个 Windows 客户端。
>
> 和 v2rayN 唯一的本质区别：v2rayN 靠 **系统代理 / Tun / 全局路由** 把流量弄进代理；我们**不碰这些**，改用 **按程序分流**（WinDivert 抓包）——只让你选中的程序走代理，其它程序一律直连、不影响系统。

本文档面向"拿去让 AI 画 UI / 写前端"的场景，因此每个模块都写清：**作用 → 界面元素 → 每个按钮 → 行为/状态**，并在第 4 节讲清"两者怎么结合"，第 5、6 节给出**已有后端 API** 和 **待补 API**，前端照着接即可。

---

## 1. 和 v2rayN 的对照（哪些照抄、哪些替换、哪些新增）

| v2rayN 里的东西 | 我们怎么处理 |
|---|---|
| 节点列表（类型/别名/地址/端口/传输/TLS/延迟/速度） | ✅ **照抄**，一模一样 |
| 订阅分组（添加/更新订阅） | ✅ **照抄** |
| 设置（内核参数、DNS、路由…） | ✅ **保留**，但路由部分换成"应用分流" |
| 重启服务、日志面板、测延迟/测速 | ✅ **照抄** |
| 本地 `mixed:10808` 入站 | ✅ **保留**，但默认只给内部分流引擎用（也可选对局域网开放） |
| **系统代理**（自动配置/全局/清除） | ❌ **去掉**，我们不设系统代理 |
| **启用 Tun**（全局接管） | ❌ **去掉**，我们不用 Tun |
| **路由模式** `V4-全局 / 规则 / 绕过大陆` | 🔄 **替换为「应用分流」**：不是按域名/IP 决定，而是**按程序**决定谁走代理 |
| （无） | ➕ **新增「应用分流」模块**（我们独有，见 3.3） |

**结论**：把 v2rayN 的左半边（节点/订阅/内核/日志/设置）几乎原样保留，把它底部那条"系统代理 / Tun / 全局模式"整条**换成我们的「应用分流」模块**。这就是"怎么结合"。

## 2. 整体界面布局

建议 **左侧导航 + 右侧内容** 结构（比 v2rayN 的顶部菜单更现代，模块也更清晰）。窗口默认 1040×720。

```
┌───────────┬─────────────────────────────────────────────┐
│  侧边导航   │  顶部状态条（当前节点 / 出口IP / 上下行 / 大启停按钮） │
│           ├─────────────────────────────────────────────┤
│ ◉ 节点     │                                             │
│ ⚑ 应用分流  │            当前模块的内容区                     │
│ ⟳ 订阅     │                                             │
│ ▤ 日志     │                                             │
│ ⚙ 设置     │                                             │
│           │                                             │
│ v1.0 状态  │                                             │
└───────────┴─────────────────────────────────────────────┘
```

顶部状态条（任何模块都常驻）：
- 左：运行指示灯（绿=已连接 / 灰=停止）＋ 当前活动节点名（如 `TWPro`）＋ 出口 IP（如 `211.76.176.116`）
- 中：实时上/下行速度（`↑ 1.2 MB/s ↓ 8.4 MB/s`）＋ 活动连接数
- 右：**大启停按钮**（"启动"绿 / "停止"红）——一键起停"内核＋分流引擎"

## 3. 各模块详述

### 3.1 节点（对应 v2rayN「配置项」＋主列表）

**作用**：管理所有代理节点。

**界面**：一个表格 ＋ 顶部工具条。列（照抄 v2rayN）：
`序号 | 类型 | 别名 | 地址 | 端口 | 传输 | TLS | 订阅分组 | 延迟(ms) | 速度(MB/s) | [活动标记]`

**工具条按钮（逐个）**：
- **分组下拉**（"所有 / 各订阅分组"）：按分组过滤列表。
- **＋ 添加**（下拉菜单）：`从剪贴板导入` / `手动添加`(选协议 vless/vmess/trojan/ss…填表单) / `扫描屏幕二维码` / `从链接添加`(粘贴一行或多行)。
- **✏️ 编辑**：编辑选中节点。
- **🗑 删除**：删除选中（支持多选）。
- **过滤器输入框**：按别名/地址关键字过滤，回车执行。
- **⚡ 测延迟**：对选中/全部节点做真连测速（TCP 或真实 HTTP 时延），结果写回"延迟"列，按快慢染色。
- **⏱ 测速**：下载测速，结果写回"速度"列。

**行为**：
- 双击某行 / 右键"设为活动" = 把它设为**当前活动节点**（列表用"活动"红标标注，见你截图里"台湾Hinet 活动"）。
- 右键菜单：`设为活动 / 编辑 / 删除 / 复制分享链接 / 显示二维码 / 上移下移 / 测此节点延迟`。
- 活动节点是全局唯一的：**应用分流里所有走代理的程序，都走这个活动节点**（进阶功能里可为单个应用指定别的节点，见 3.3）。

---

### 3.2 订阅（对应 v2rayN「订阅分组」）

**作用**：从订阅链接批量拉取/更新节点。

**界面**：订阅列表 ＋ 按钮。每条订阅：`名称 | URL | 节点数 | 上次更新时间 | [自动更新开关]`。

**按钮（逐个）**：
- **添加订阅**：填 `名称 + 订阅URL + 更新时是否走代理(开关)`。
- **更新**：`更新全部` / `更新选中`——拉取并合并进对应分组。
- **编辑 / 删除**：改或删一条订阅。
- **自动更新**：设间隔（如每 6 小时）。

---

### 3.3 ⭐ 应用分流（我们独有，替换 v2rayN 的"系统代理/Tun/全局模式"）

**作用**：**这就是整个产品的核心**。决定"哪些程序走代理"。不在列表里的程序 = 一律直连，完全不受影响。

**界面**：一个应用规则列表 ＋ 顶部按钮 ＋ 底部兜底策略。

每行一个应用：
`[图标] 程序名(exe) | 完整路径 | 动作下拉 | [启用开关] | [删除]`
- **动作下拉**：`走代理(proxy)` / `直连(direct)` / `阻断(block)`（默认走代理）。
- **启用开关**：临时停用某条规则而不删除。
- （进阶，可后置）**指定节点**：该应用走哪个节点/分组，默认"跟随活动节点"。

**顶部按钮（逐个）**：
- **＋ 添加应用**（下拉）：
  - `从运行中的程序选择`：弹出当前运行进程列表（可搜索，显示 `exe 名 + 路径 + 进程数`），勾选加入。← 后端已就绪
  - `浏览 .exe 文件`：文件选择器选一个可执行文件（按完整路径匹配）。
  - `手动输入`：直接填 `code.exe` 这种名字（按文件名匹配）。
- **🗑 删除**：移除选中规则。

**底部**：
- **兜底策略**：未列出的应用 = `直连`（默认，建议锁死不让改，避免误伤系统）。
- **匹配说明**（一行小字）：可按 **exe 文件名**（如 `code.exe`，会命中所有同名进程）或 **完整路径** 匹配；提示 `node.exe 之类会命中系统里所有 node 进程，必要时用完整路径`。

**行为**：
- 规则可在**运行中实时增删**，立即生效（后端 `SetApps` 支持热更新）。
- 命中规则的程序：它的 TCP 连接被 WinDivert 抓取 → 转发进活动节点；未命中的原样直连。

---

### 3.4 日志（对应 v2rayN 底部日志面板）

**作用**：实时看内核 + 分流引擎 + 每条连接。

**界面/按钮（逐个）**：
- 日志滚动区（等宽字体）。
- **过滤器（支持正则）**：过滤显示。
- **自动刷新** 开关 / **自动滚动到末尾** 开关（照抄 v2rayN）。
- **清空** / **复制** 按钮。
- **日志级别** 下拉：`trace/debug/info/warn/error`。
- 每条连接理想格式：`时间 | 应用(exe) | 源端口 → 目标地址:端口 | 走了哪个出站(节点/直连)`。（当前后端已输出 `[divert] code.exe 1.2.3.4:5 → ...`，可继续细化。）

### 3.5 设置（对应 v2rayN「设置」）

分区列出：
- **内核**：sing-box（已内置，显示版本）；本地入站端口 `mixed`（默认自动，可手填如 10808）；是否对**局域网**开放该 SOCKS（对应 v2rayN 的"本地/局域网"两行）。
- **分流引擎**：WinDivert 优先级；是否排除自身/内核进程（默认开）；私网直连开关（命中应用访问局域网/私有 IP 时不走代理，*待做*）。
- **DNS**：远程 DNS / fake-ip（防污染泄漏，*待做*）。
- **QUIC**：`阻断 QUIC 以回落 TCP` / `放行`（*待做*）。
- **系统**：开机自启 / 最小化到托盘 / 关闭到托盘（*待做*）。
- **外观**：主题（深/浅/跟随系统）、语言。
- **关于**：版本、检查更新、开源许可。

### 3.6 顶部/托盘 的全局操作（对应 v2rayN「重启服务/退出」和托盘）

- **启动 / 停止**（顶部大按钮）：起停"内核＋分流引擎"。← 后端已就绪
- **重启**：重启内核（换节点后自动重启）。
- **托盘图标**：右键 `显示主界面 / 启动·停止 / 切换节点 / 退出`（*待做*）。

## 4. ⭐ 怎么结合（这是你最关心的那句话）

### 流量走向（和 v2rayN 的根本差别就在这）

```
v2rayN：  所有流量 ──(系统代理/Tun/全局)──► 内核 ──► 节点 ──► 互联网
                     ↑ 全局接管，别的服务受影响

我们：    只有被选中的程序
          app ──► WinDivert 抓包 ──► 本地 redirector ──► 内核(sing-box, SOCKS) ──► 活动节点 ──► 互联网
          其它所有程序 ─────────────────────────────────────────────────────► 直连（毫不受影响）
```

### 缝合规则（一句话讲清每个衔接点）

1. **节点/订阅/内核**：完全等同 v2rayN——我们也内置 sing-box，加节点、订阅、测速、日志都一样。
2. **"活动节点"是共享的**：应用分流里所有"走代理"的程序，统一走当前活动节点。（进阶：允许单个应用指定别的节点。）
3. **去掉系统代理和 Tun**：v2rayN 底部那条 `启用Tun / 清除系统代理 / V4-全局` 整条**不要**，换成"应用分流"模块。
4. **本地 `mixed` 端口**：v2rayN 是暴露给系统/浏览器用；我们是**内部**给分流引擎当上游（`redirector → SOCKS → 内核`）。可选对局域网开放（保留 v2rayN 那个"局域网"能力）。
5. **模式选择**：v2rayN 的"全局/规则/绕过大陆"没有了；我们的"模式"就是**应用清单本身**——清单＝规则。

## 5. 已有后端 API（前端直接调，已实现并测过）

后端是 Go(Wails) 绑定，前端 `import { X } from '../wailsjs/go/main/App.js'` 即可用。

| 方法 | 作用 | 返回 |
|---|---|---|
| `AddNodes(text: string)` | 粘贴分享链接（多行）解析入库，自动去重 | `{added, skipped}` |
| `GetNodes()` | 取节点列表 | `Node[]`（含 id/name/type/server/port/…） |
| `RemoveNode(id)` | 删节点 | — |
| `SelectNode(id)` | 设为活动节点 | — |
| `GetApps()` | 取应用分流规则 | `string[]`（exe 名或完整路径） |
| `SetApps(apps: string[])` | 覆盖式设置规则（**运行中热更新**） | — |
| `ListProcesses()` | 取当前运行进程（给"从进程选择"用） | `{name, path, count}[]` |
| `Start()` | 起内核＋分流引擎 | `string`（空=成功，否则错误文本） |
| `Stop()` | 全停 | — |
| `GetStatus()` | 状态快照（轮询 1s） | `{coreRunning, engineRunning, corePort, nodeName, selectedId, apps[], stats{activeConns,totalConns,tracked}}` |
| 事件 `EventsOn('log', cb)` | 实时日志流（内核+引擎每一行） | `string` |

`Node` 结构字段：`id, name, type(vless/vmess/trojan/shadowsocks), server, port, uuid, password, method, security, sni, flow, network, ...`

## 6. 待补后端 API（UI 需要、我来补）

UI 设计好后，以下后端我按需补齐（把它们当作"承诺会有的接口"来设计）：

- **节点**：`TestLatency(id) / TestAllLatency()`（测延迟写回）；`EditNode(id, fields)`；`AddNodeManual(fields)`；`ExportLink(id) / QRCode(id)`；`Reorder(ids)`。
- **订阅**：`GetSubs / AddSub / UpdateSub(id) / UpdateAllSubs / RemoveSub`。
- **应用分流（需要把规则从 `string[]` 升级成结构体）**：
  `AppRule = { match: string, byPath: bool, action: 'proxy'|'direct'|'block', enabled: bool, nodeId?: string }`
  对应 `GetAppRules() / SetAppRules(rules[])`。
- **设置**：`GetSettings() / SetSettings(s)`（端口、DNS、QUIC、私网直连、自启、主题…）。
- **流量**：`TrafficStats` 事件（每秒上/下行字节，画速度曲线）。
- **系统**：开机自启、托盘。

> 现在的 `GetApps/SetApps(string[])` 够做 MVP；等 UI 定稿要"动作/开关/指定节点"时，我把它升级成上面的 `AppRule` 结构。

## 7. 视觉/交互建议（不强制，供设计参考）

- 深色为主、可选浅色；一个强调色（青/蓝）。
- 列表密度参考 v2rayN，但圆角卡片化、留白多一点。
- 顶部状态条常驻、启停按钮永远显眼。
- 关键状态用颜色：绿=连接/低延迟，黄=中，红=高/停止。
- 空状态有引导（"还没有节点，去粘贴链接"）。
