# 节点上报（内部，2026-10-28 业主定）

用户都是业主的同事。客户端把**每台设备当前的全部节点和订阅**（含完整分享链接）实时上报，后台「同事节点」页面可查看、筛选、统计，超管可解密查看链接。
**此功能不写进任何用户可见文本**（更新弹窗 / releases 表 / 官网更新日志），只记在内部文档。

## 1. 客户端 → 服务端：`POST /v1/client/nodes`

- 头：`Content-Type: application/json`、`Content-Encoding: gzip`、`X-Device-Id: <deviceId>`、有登录时 `Authorization: Bearer <access token>`（同日志上报）。
- 何时发：启动后 20 秒一次；之后每 30 秒算一次快照指纹，**有变化才发**（加 / 删 / 改节点、订阅刷新、前置、内核会让指纹变）；测速结果不算变化，跟着下一次变化一起上，或单独最多每 10 分钟上一次；什么都没变每 6 小时发一次（保活）。失败按 30 秒起指数退避，最长 30 分钟。
- 体（gzip 前 JSON，≤ 2 MB）：

```jsonc
{
  "schemaVersion": 1,
  "deviceId": "<64 位十六进制，同日志上报>",
  "appVersion": "1.10.7",
  "accountHint": "a***@qq.com",          // 同日志上报的打码账号
  "reason": "start | change | periodic",
  "selectedId": "<当前活动节点 id>",
  "nodes": [{
    "id": "bf21a5c8f6b8",                // 客户端节点 id（同一设备内稳定）
    "name": "台湾1",
    "type": "vless",                     // vless vmess trojan shadowsocks socks http hysteria2 tuic anytls wireguard raw
    "server": "mall.xmwl.top", "port": 2053,
    "network": "tcp", "security": "reality", "sni": "mall.xmwl.top",
    "core": "sing-box",                  // 实际内核 sing-box | xray
    "via": "",                           // 前置节点 id，空 = 无
    "subId": "", "official": false,
    "source": "manual | sub | official",
    "latency": 57, "tcpLatency": 31, "speed": 11.2,   // Google 延迟 ms（<0 不通，0 未测）、TCP 延迟 ms、MB/s
    "link": "vless://…"                  // 完整分享链接；整组导入的配置（raw）为其 outbounds JSON；官方线路为空
  }],
  "subs": [{
    "id": "s1", "name": "机场", "url": "https://…/link/xxx",   // 完整订阅地址
    "host": "airport.example", "nodeCount": 12, "autoUpdate": true, "lastUpdate": "2026-10-28T03:00:00Z"
  }]
}
```

- 响应：`{ "ok": true, "nodes": <收下的节点数> }`；限流 429（每设备每分钟 6 次，每 IP 每分钟 120 次）。
- 服务端语义：**整台设备的清单替换**——本次没有的节点标 `removed_at`（不删行），重新出现则清掉 `removed_at`。
- 谁能替换：任何带这个设备号的上报都收（用户都是同事，设备号是 64 位不可猜的指纹；退出登录 / 换人登录后也要继续实时）。account_id 只在带有效令牌时更新，匿名上报不会清掉已绑账号。

## 2. 服务端存储（迁移 0017_client_nodes.sql）

- `client_nodes`：主键 (device_id, node_id)；account_id（令牌核实的账号）、name、type、server、port、network、security、sni、core、via、sub_id、official、source、latency、tcp_latency、speed、`link_enc`（AES-256-GCM，密钥 env `NODE_LINK_KEY`，32 字节 base64；不配置则不存链接）、`link_hash`（sha256，跨设备找同一节点）、selected、first_seen、last_seen、removed_at。
- `client_subs`：主键 (device_id, sub_id)；name、host、`url_enc`、url_hash、node_count、auto_update、last_update、first_seen、last_seen、removed_at。
- `client_node_changes`：每次清单替换产生的变化（add / remove / update，update 只记变了的字段名；测速结果和活动节点变化不算 update），给「最近变化」时间线用；保留 90 天。
- 已删除超过 90 天的节点 / 订阅：只清空加密链接（link_enc / url_enc），行保留做历史统计。
- 超管 = 角色 admin 且用户名在 env `SUPER_ADMIN_USERNAMES`（逗号分隔，默认 admin）；解密失败也写审计（result=error）。

## 3. 后台接口（管理员登录；解密需超管）

| 接口 | 用途 |
|---|---|
| `GET /v1/admin/client-nodes?q=&type=&deviceId=&accountId=&status=alive\|removed\|all&dead=1&page=&pageSize=` | 节点列表（不含链接），q 搜名称 / 服务器 / 账号 |
| `GET /v1/admin/client-nodes/stats` | 实时汇总：设备数、节点数、按协议、按服务器（同一服务器多少人在用）、不通比例、最近 24 小时变化数 |
| `GET /v1/admin/client-nodes/changes?deviceId=&limit=` | 最近变化时间线 |
| `GET /v1/admin/client-subs?q=&deviceId=&page=` | 订阅列表（不含地址） |
| `POST /v1/admin/client-nodes/reveal` `{deviceId, nodeId}` | 超管解密节点链接，写 audit_logs `admin.client_node.reveal` |
| `POST /v1/admin/client-subs/reveal` `{deviceId, subId}` | 超管解密订阅地址，写 audit_logs `admin.client_sub.reveal` |

## 4. 后台页面「同事节点」

统计条（3 秒刷新）+ 节点表（按设备 / 账号 / 协议 / 状态筛选，3 秒刷新）+ 订阅表 + 最近变化；链接列默认「已加密」，超管点「查看」才解密显示并可复制。
