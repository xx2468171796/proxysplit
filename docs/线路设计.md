# 设计：每应用线路 + 分流策略 + 多节点分流

## 目标（你的三个诉求）
1. **每个应用**能单独选:走**直连** / 走**全局** / 走**规则**（分流）。
2. **黑名单 / 白名单**：控制"没被列出的应用"默认怎么走。
3. **多应用走不同线路**：应用 A 走日本节点，应用 B 走美国节点，应用 C 直连……

核心概念就一个词：**线路 (Line)**。把这三件事统一起来。

---

## 1. 线路 (Line) = 出口节点 + 分流策略

一条线路 = 「**从哪个节点出去**」+「**这条线路内部怎么分流**」。

```
Line {
  name      显示名，如 "日本-规则" / "美国-全局" / "直连"
  出口      active(跟随当前活动节点) | 某个具体节点 | direct(不走节点) | auto(自动选最快, 后续)
  分流      global(全走这个出口) | rule(按规则:绕过大陆/自定义) | (出口=direct 时即全直连)
}
```

**内置线路（永远存在，傻瓜化默认）：**
| 线路 | 出口 | 分流 | 含义 |
|---|---|---|---|
| **直连** | — | — | 不走代理，直接连网 |
| **全局** | 当前活动节点 | global | 这个应用所有流量都走节点 |
| **规则** | 当前活动节点 | 绕过大陆 | 国内直连、国外走节点（智能分流）|
| **拦截** | — | — | 直接断掉（如广告进程）|

**自定义线路（你自己建）：** 例如
- `美区-全局` = 出口 美国节点 · 全局
- `日区-规则` = 出口 日本节点 · 绕过大陆
- `香港-自定义` = 出口 香港节点 · 自定义规则(你写的域名/IP)

---

## 2. 应用规则 → 指定一条线路

每个应用规则从原来的「动作(走代理/直连/拦截)」升级成「**选一条线路**」：

```
AppRule {
  应用      code.exe / 完整路径
  线路      直连 | 全局 | 规则 | 拦截 | <你建的某条线路>
  启用      开关
}
```

于是"多应用走不同线路"就是：Code.exe → `日区-规则`，Chrome.exe → `美区-全局`，微信 → `直连`。一目了然。

---

## 3. 黑名单 / 白名单 = 「没列出的应用」默认走哪条线路

| 模式 | 列出的应用 | **没列出**的应用 |
|---|---|---|
| **黑名单**（默认，最安全）| 走各自指定的线路 | **直连**（不受影响）|
| **白名单** | 走各自指定的线路（通常设"直连"当例外）| 走一条**默认线路**（你选，如"规则"）|

黑名单 = "只有我挑的应用走代理"；白名单 = "除了我挑的，其它都走代理"。

---

## 4. 技术实现（关键，决定可行性）

难点：我们是"重定向"模型,sing-box 只看到我们转发进去的 SOCKS 连接,**它不知道是哪个应用发的**。所以"不同应用走不同节点/策略"不能靠 sing-box 自己按进程分——要靠**多入站(inbound)**。

**做法：一条在用的线路 = sing-box 里一个专属入站口。**
```
sing-box 配置（自动生成）:
  inbounds:  in-日区规则(:20001)  in-美区全局(:20002)  ...   ← 每条在用线路一个口
  outbounds: node-日本  node-美国  direct                    ← 用到的节点去重
  route.rules:                                               ← 按入站口路由
    {action: sniff}
    # 日区规则这条线路:
    {inbound:[in-日区规则], rule_set:[geosite-cn,geoip-cn], outbound:direct}
    {inbound:[in-日区规则], outbound: node-日本}   # 兜底
    # 美区全局这条线路:
    {inbound:[in-美区全局], outbound: node-美国}
  final: direct
```

**引擎侧（sing-box TUN + `process_name` 路由）改造：**
- 匹配某应用 → 查它的线路 → 转发到**那条线路的入站端口**（现在是单一上游,改成"每条线路一个上游 dialer"）。
- 应用=直连 → 引擎直接放行不重定向；应用=拦截 → 丢包。
- conntrack 里给每条流记住它属于哪条线路,回程/转发时用对应上游。

这套是干净可行的:sing-box 的 `inbound` 路由匹配是原生能力,引擎多上游也就是加个 `map[线路]→dialer`。

## 5. 界面（保持傻瓜化）

**应用规则表**:把现在的"动作 + 节点"两列合并成**一个「线路」下拉**：
```
应用程序        线路 ▼            启用   操作
Code.exe        [日区-规则 ▼]      ●     🗑
chrome.exe      [美区-全局 ▼]      ●     🗑
微信.exe         [直连 ▼]          ○     🗑
   下拉内容: 直连 / 全局 / 规则 / 拦截 / ──── / 日区-规则 / 美区-全局 / + 新建线路…
```

**新增「线路」管理区**(可以在设置页或独立小页):
```
线路管理                                    [+ 新建线路]
日区-规则    出口: 日本-Tokyo    分流: 绕过大陆   ✎ 🗑
美区-全局    出口: 美国-LA       分流: 全局       ✎ 🗑
新建线路: 名称[____] 出口[选节点▼] 分流[全局/绕过大陆/自定义▼]
```

顶部「黑名单/白名单」开关 + (白名单时)"默认线路"选择。

傻瓜化保证:**不建任何自定义线路也能用**——每个应用直接在"直连/全局/规则"里选就行,想要"某应用单独走别的节点"时才去建线路。

## 6. 数据模型（Go / 持久化）

```go
type Line struct {
    ID      string   `json:"id"`      // 内置: direct/block/global/rule; 自定义: 生成
    Name    string   `json:"name"`
    Node    string   `json:"node"`    // "active" | 节点id | "direct"
    Routing Routing  `json:"routing"` // {mode: global|bypass_cn|custom, rules}
    Builtin bool     `json:"builtin"`
}

type AppRule struct {
    Match   string `json:"match"`
    Path    string `json:"path"`
    Line    string `json:"line"`    // 线路 id (替代原 action/follow/nodeId)
    Enabled bool   `json:"enabled"`
}

type Config {
    ...
    Lines       []Line     // 自定义线路（内置的运行时注入）
    Rules       []AppRule
    RuleMode    string     // blacklist | whitelist
    DefaultLine string     // 白名单时,未列出应用走的线路
}
```

## 7. 实施计划（分步，可多 agent 并行）

1. **service/core**:Line 模型 + 多入站/多出站 sing-box 配置生成（每条在用线路一个 inbound + 按 inbound 的 route 规则）。用 `sing-box check` + 真机验证"两个应用两个节点"。
2. **engine**:Matcher.Decide 返回 `{action, lineID}`;conntrack 存 lineID;handleConn 按线路选上游 dialer(多上游)。
3. **app.go/绑定**:Lines CRUD + 规则改成选线路 + DefaultLine。
4. **UI**:规则表"线路"下拉 + 线路管理区 + 黑/白名单默认线路。
5. **审计 + 真机验证**:应用 A 走节点1、应用 B 走节点2、应用 C 直连,同时验证。

---

## 与现有功能的关系
- 现在的"应用规则(proxy/direct/block)"→ 平滑迁移成 线路(全局/直连/拦截)。
- 现在的"分流模式(全局/绕过大陆/自定义)"→ 变成**每条线路各自的分流**。
- 现在的"分流总开关"→ 保留为"一键全局"覆盖(关=所有应用临时按全局走活动节点)。
- 已内置的 geosite/geoip 规则集、远程DNS、QUIC阻断 → 全部复用。
