# ProxySplit 商业化实施计划

> 状态：UI 原型已确认；核心代理与持久化已验收。后续改造不得破坏节点、应用规则和启动链路。

## 最终目标

1. 正式客户端采用已确认的 `ProxySplit-UI-Prototype-v2.html` 布局，并接回全部真实功能。
2. 补齐规则体系：规则库、自定义规则、自定义线路、应用绑定、更新、校验、导入导出和持久化。
3. 增加可售卖的用户名密码与授权体系：套餐、到期时间、设备绑定、封禁、离线宽限和版本策略。
4. 建设服务端 API 与运营管理后台。
5. 建立发布加固链：代码签名、完整性校验、服务端授权、混淆和敏感信息边界。

## 不变边界

- 不重写已经验收的代理核心、节点解析、应用分流和配置三重备份。
- UI 改造只调用现有 Wails 绑定；需要新增能力时先补后端接口和测试。
- 用户节点、订阅、应用规则继续保存在本地；服务端不上传代理节点明文。
- 密码、私钥、JWT 密钥、签名私钥不进入客户端和 Git 仓库。
- “防反编译”按提高成本设计，不能承诺绝对不可反编译；真正的授权判定必须由服务端掌握。

## 阶段 0：清理与基线（本轮已开始）

- 清除旧版本 exe、调试 exe、临时截图、日志和下载缓存。
- `output/` 只保留当前发布版、便捷副本、用户数据副本、README 和已确认的 UI 原型。
- 保留可复现构建脚本、测试与设计原型源文件。
- 建立功能清单，迁移期间逐项勾选，避免“换皮后功能丢失”。

验收：工作区干净；旧文件不参与构建；正式 v1.7.2 仍可读取现有数据。

## 阶段 1：正式 UI v2

### 页面

- 概览：状态、活动节点、应用规则、流量、链路健康、快捷入口。
- 节点：左侧导入/手动添加，右侧搜索、测速、选择、二维码和删除。
- 应用分流：规则统计、白名单/黑名单、进程/文件选择、线路与节点、启停和测试。
- 分流规则：规则库、自定义全局规则、自定义线路、更新状态。
- 订阅：新增、更新、自动更新、删除和节点数量。
- 日志：级别筛选、复制、清空和错误突出。
- 设置：网络/内核、系统集成、外观维护、配置导入导出。

### 实施方式

- 将当前单文件 `App.svelte` 拆为 `lib/state`、`lib/components`、`pages`。
- 先迁移状态和动作，不改业务语义；再替换布局和样式。
- 每迁移一页执行 Svelte 类型检查和对应持久化/运行验证。

验收：7 页全部使用真实数据；旧功能清单 100% 映射；无演示数据进入生产路径。

## 阶段 2：规则体系补齐（当前优先）

### 规则库

- 展示文件存在性、版本日期、大小、启用状态和最后更新结果。
- 国内域名、国内 IP、广告拦截可以分别启停。
- 更新采用临时文件下载、格式校验、原子替换；失败保留旧规则。

### 自定义规则

- 类型：完整域名、域名后缀、关键字、IP/CIDR。
- 动作：代理、直连、拦截。
- 保存前校验类型、值和动作；规范化大小写与空格；去重并保持顺序。
- 修改后若核心运行则安全重载；失败写日志并返回界面错误。

### 自定义线路与应用绑定

- 线路名称、节点、模式和规则必须校验。
- 禁止占用内置 ID、重复 ID、重复名称和引用不存在节点。
- 删除线路前提示被哪些应用引用；确认后将引用迁回“规则”线路。
- 应用规则只允许引用存在的线路，空路径、重复匹配和非法动作不能落盘。

### 导入导出

- 独立导入导出：应用规则、全局规则、线路；带 schema 版本。
- 导入先预检并展示新增/覆盖/跳过数量，确认后原子保存。

验收：正反例单元测试、重启持久化、运行中重载、损坏输入不污染配置。

## 阶段 3：商业授权服务端

建议采用中犇标准 `vite-fastify-monorepo`：React 管理后台 + Fastify API + PostgreSQL + Redis。

### 核心实体

- `users`：用户名、Argon2id 密码哈希、状态、角色。
- `plans`：套餐、设备数、有效期、功能权限。
- `licenses`：授权码、用户、套餐、开始/到期、状态。
- `devices`：设备指纹摘要、设备名、首次/最后在线、解绑状态。
- `sessions`：refresh token jti 轮换链和吊销状态。
- `releases`：客户端版本、最低允许版本、下载地址、SHA256、签名。
- `audit_logs`：管理员操作、登录、授权与设备变更。

### 客户端登录与授权

- 用户名密码登录；Argon2id；access/refresh 双 token。
- 登录成功后领取短期、服务端签名的 license lease。
- lease 包含用户、套餐、设备、功能、到期和最小版本；客户端只内置公钥验签。
- 支持有限离线宽限；封禁、退款、超设备数和强制升级由服务端判定。
- 设备指纹只传不可逆摘要，不采集无关隐私。

### 安全基线

- 登录错误不暴露账号是否存在；登录/刷新限流。
- refresh token 每次轮换，旧 token 重放则吊销整条链。
- 管理后台使用 `requireAdmin` / `requirePermission`，不能只隐藏菜单。
- 服务端密钥由 Infisical 注入；生产使用 PG/Redis；全链路审计。

## 阶段 4：运营管理后台

- 仪表盘：用户、有效授权、在线设备、即将到期、版本分布。
- 用户：创建、重置密码、封禁、备注、查看设备与登录日志。
- 套餐与授权：开通、续费、暂停、退款标记、设备数和功能权限。
- 设备：解绑、强制下线、黑名单。
- 版本：上传发布信息、灰度、强制升级、下载校验。
- 审计：管理员、动作、对象、IP、结果、时间，不记录密码和完整 token。

## 阶段 5：客户端发布加固

- Windows Authenticode 代码签名；安装包和 exe 同时签名。
- 构建继续使用 `-trimpath -s -w`，再评估兼容 Wails 绑定的 Go 混淆方案。
- 启动时校验嵌入资源与核心文件哈希；发布清单由服务端私钥签名。
- 客户端只放验签公钥，不放服务端密钥、数据库凭据或可离线生成授权的秘密。
- TLS、证书公钥固定、反调试/反篡改作为加固层；校验失败安全退出并写最小日志。
- 授权与高级功能采用服务端下发的短期能力声明，避免仅靠本地布尔值破解。

## 版本节奏

- `v1.8.0`：正式 UI v2 + 完整规则体系。
- `v1.9.0`：登录、设备绑定、授权服务端和基础管理后台。
- `v2.0.0`：商业发布、版本管理、代码签名与完整加固链。

每个版本都必须执行：自动测试 → 隔离配置 GUI 验收 → 正常退出重开 → 产物哈希 → Gitea 提交/标签 → 中枢汇报。
